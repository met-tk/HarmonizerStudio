# 核心和弦识别与算子适配约定

## 数据边界

- `ChordClassifier::identifyChord(notes, tonic, scale, tonicName)` 将传入的全部选中音符对象视为一个和弦，包括静音但仍被选中编辑的对象。它不按起始拍重新分组。需要按时间分析和弦进行时，由调用方使用 `identifyChordGroups`；分组入口保留相同的选中对象语义。若调用方需要只分析发声音符，应在进入两个接口前显式过滤静音对象。
- 音高类别用于识别和弦公式；真实最低 MIDI 音决定斜杠低音。八度重复不会增加和弦音种类，但 `noteIds` 与 `noteRoles` 保留每个输入音符。
- `fullName` 是当前最佳解释；`alternatives` 是其他可辩护的解释，不能把主名视为唯一乐理事实。每个候选包含独立的根音、实际低音、级数、音程掩码、转位与逐音角色，可供后续算子明确选择解释。复合和弦具有 `isPolychord`、下层根音 `rootPitchClass`、上层根音 `upperRootPitchClass`、两层转位和分层音高边界 `polychordSplitPitch`；每个 `noteRoles` 项标出所属层。
- `status` 与 `confidence` 决定结果可否作为算子输入。单音、普通双音和无法识别的密集音簇不应被当成确定的完整和弦。属功能判断应检查实际大三度和小七度。
- `getSupportedQualities()` 公布可识别的和弦公式、同义写法和 `acceptedVoicings`；十三和弦省略十一度等常见排列在该字段中明示。添加品质时同时更新识别公式和此公开目录。

## 识别顺序

1. 精确比对结构明确的三和弦、六和弦、七和弦、延伸和弦及变化和弦。
2. 比对常见缺五度，以及含已知附加音的结构；省略和附加音分别记录。
3. 对无根音的七和弦给低权重候选，让有根音的完整解释优先。
4. 当上下两个三和弦在音域上明显分开时，考虑复合和弦；有下层根音的完整延伸和弦优先，其余完整统一解读以候选保留并标出歧义。双层转位分别保留在名称和结构化字段中。
5. 用真实低音、调式和拼写语境消解同音集歧义，仍保留其他候选。

调式级数由调式的实际音程推得。例如 C 多利亚的 B♭ 大三和弦是 `bVII`；F 大调的 B♭ 大三和弦是 `IV`。同音异名由调式推断常用主音拼写，也可通过 `tonicName` 明确指定（例如 C♯ 自然小调与 D♭ 自然小调）。没有目标和弦或进行上下文时，级数只表示当前和弦相对主音的位置，不应凭一个音集臆断副属功能。

## 算子接入

- 算子首先识别**用户实际选择的音符对象**；不支持的单音、普通双音、复合和弦或音簇应明确拒绝，除非该算子提供了专门规则。
- 改写方案要保留原始音符的 ID、拍位、时值、力度、静音和选中状态；同一音高声部的重复事件应同步改变。
- 用 `materialiseChordPlan` 将 changed、added、removed 应用于原音符组，再用 `identifyPlannedChord` 识别真正将出现的音符。预览名称必须取此结果的 `fullName`，不得用算法预期的模板名代替。
- 副属和弦同时记录生成和弦名、目标和弦名或已知目标根音、以及 `V/目标级数`。显式指定目标音允许从单音生成；自动推断和弦根音需满足完整和弦识别条件。放置多个生成组后，默认只选中第一组，供单和弦分析栏显示；所有组都会写入片段。
- 添加新算子时优先使用 `rootPitchClass`、`bassPitchClass`、`family`、`intervalMask`、`noteRoles`、`omittedIntervals` 等结构化属性，不应解析 `fullName` 来决定音高操作。

## 参考资料与验证

`chordieapp` 目录中的逆向资料用于扩充公式和构造测试样本，并非无条件正确的规范。其 Python 版本含重复公式、无法到达的八度模板、随声部排列变化的“转位”数字，也不提供真实的调式拼写。核心实现重新定义了这些行为。执行 `--run-chord-theory-tests` 可运行固定乐理样本与跨算子一致性验收；其他自检入口仍覆盖重配、和弦编辑、副属和弦、调式、项目读写和撤销。
