# 代码审查与修复记录（2026-10-16）

## 范围与方法

审查了项目的构建配置、`src` 下的核心模型、工程与 MIDI 读写、音频和 VST3 宿主、主要 UI 异步路径，以及项目内置的 JUCE 版本。结合静态阅读、Release 构建、现有撤销测试和新增的工程文件回归测试进行验证。本记录只列出有代码证据支持的结论；它不代表形式化安全证明。

## 已修复问题（按优先级）

| 优先级 | 问题与影响 | 修复 |
| --- | --- | --- |
| 严重 | JUCE 9.0.2 构造畸形 UTF-8 字符串时，分配长度和写入长度可能不一致 | 从 JUCE 官方提交 [`330ef16`](https://github.com/juce-framework/JUCE/commit/330ef16fa0d04bf36d843c7811e0f1d5a31b2c66) 单独移植 `juce_String.cpp` 修复；保留原有 `juceaide/Main.cpp` 本地修改。内置库仍标记为 9.0.2，属于定点回移补丁。 |
| 严重 | 工程文件中的 VST 状态长度未经检查就传入 JUCE 解码器，可触发异常大的内存分配 | 严格验证长度前缀、编码长度和字符集；限制单个状态为 128 MiB、工程文件为 256 MiB；异常文件拒绝加载且不改动当前工程。 |
| 高 | 工程文件加载中途失败可能留下部分新状态，保存失败可能覆盖原文件 | 先校验并装载到临时模型，再提交；项目文件使用临时文件覆盖；保存、打开失败向用户显示错误。 |
| 高 | 工程保存遗漏轨道音量/声像、调式、速度变化、显示设置等数据；加载后轨道 ID 可能重复 | 补齐序列化，恢复后重算 ID；加入正常往返与唯一性测试。 |
| 高 | MIDI 导入未正确区分通道上的同音音符、SMPTE 时间格式处理不正确；导出时音符位置重复叠加片段起点、静音轨可能导出音符、速度和拍号变化丢失 | 修正配对与时间换算、导出位置及过滤逻辑，并加入对应回归测试。 |
| 高 | 异步菜单、对话框、浮动窗关闭回调可能在所属组件销毁后访问裸指针 | 使用 JUCE `Component::SafePointer` 校验组件生存期；清理不再使用的对话框参数和字段。 |
| 高 | 插件扫描线程和 UI 共用插件列表、格式管理器及状态文本，可能形成数据竞争 | 扫描线程使用独立对象，结果返回消息线程合并；状态访问加锁；关闭编辑器走受管理的异步更新。 |
| 高 | Kontakt 实际启用 64 路输出，而宿主实时回调只提供 2 路缓冲区，选中插件后首次处理音频时发生访问异常 | 根据插件实际输入/输出通道数预分配处理缓冲区，处理完成后将可播放的前两路复制到设备输出；限制异常通道数和缓冲区大小；UI 按当前音频设备参数加载插件，并在加载失败时保持内置乐器可用。 |
| 高 | 乐器轨原先共用单个 VST 实例，切换一条轨道的音源会影响其他轨道；复制轨道时还会复用轨道 ID | 按轨道 ID 管理独立的插件实例、MIDI 队列和音频处理状态；每条乐器轨单独渲染并混音；复制轨道分配新 ID，保留独立音源及状态。 |
| 中 | 钢琴卷帘窗切换到其他轨道的音符后，VST 选择仍显示原轨道 | 轨道或片段焦点变化时同步检查器中的 VST 选择、编辑器按钮和音量/声像；插件身份标识随工程保存、载入及复制恢复。 |
| 中 | 在编曲区先切换轨道再选择片段时，钢琴卷帘窗可能仍显示上一轨道的音符 | 轨道与片段通过同一个切换入口更新，先保存旧片段编辑内容，再载入目标片段音符；增加跨轨切换回归测试。 |
| 中 | 音频线程读取可变速度事件和部分工程设置 | 使用预计算的只读速度快照及原子设置值；保留播放快照中的音符绝对拍位置。 |
| 中 | UI 工作区和配置文件中的无效数值可能造成异常布局；配置写入中断可能损坏旧文件 | 校验范围和非有限值，恢复工作区排序，使用临时文件写入 UI 与 VST 配置。 |

## 尚存风险

| 优先级 | 风险 | 后续处理方向 |
| --- | --- | --- |
| 高 | VST3 扫描与运行仍在应用进程内执行；恶意或有缺陷的插件可使宿主崩溃、卡死或执行任意代码。 | 设计独立扫描进程；运行时隔离需另行评估插件 UI、实时音频和状态迁移。 |
| 中 | 音频回调中仍有锁和可能的动态分配，在大工程或插件阻塞时可能产生爆音。 | 对最大事件量与设备缓冲进行压力测试，再分阶段替换为预分配数据结构和非阻塞队列。 |
| 中 | 模型仍向 UI 暴露若干可变容器引用，依赖调用方主动触发快照与通知，漏调用会导致播放或撤销状态滞后。 | 逐步收敛到模型提供的修改接口，并以操作行为测试保护编辑手感。 |
| 低 | 内置 JUCE 仍为 9.0.2 基线，只有本次确认的字符串安全提交被回移。 | 安排完整的 9.0.4 升级与跨平台回归，保留现有 `juceaide` 本地修改。 |

以上剩余项目涉及插件隔离或广泛的实时/数据层重构。本次没有在缺少相应端到端测试时直接替换这些架构，以免影响现有编辑和播放行为。
